FISHIQ
SMART FISHING LATAM
Brief técnico para cotización y desarrollo del MVP — v1.0
Mercado piloto: Panamá  |  Preparado para: Richard Rojas  |  Octubre 2026
OBJETIVOConstruir una web-app/PWA móvil que combine datos ambientales, conocimiento por especie y registros reales de capturas para producir un FISHIQ Score (0–100), explicar por qué una ventana es favorable y aprender progresivamente de los resultados de los pescadores.
Principio del MVP: predicción de pesca, NO navegación marítima.

2. Mercado piloto y especies
Geografía inicial: Pacífico de Panamá, con zonas piloto en Golfo/Bahía de Panamá y costa accesible; arquitectura preparada para añadir Caribe, Gatún, Bayano y otros países sin reescribir el núcleo.
Especies MVP recomendadas: róbalo, jurel, pargo, corvina, dorado/mahi-mahi, atún, wahoo y sábalo/tarpon.
Cada especie debe tener parámetros editables desde el panel administrativo: profundidad, temperatura, marea, corriente, viento, hora, temporada y técnicas.
Los lagos Gatún y Bayano pueden entrar como piloto 1B cuando se definan fuentes de nivel/meteorología y especies de agua dulce.
3. Flujo principal del usuario
1) Usuario abre FISHIQ → selecciona zona o usa ubicación.
2) Selecciona especie objetivo y fecha/hora (ahora, mañana o próximos días).
3) Backend consulta/cachéa condiciones ambientales.
4) Motor determinístico calcula FISHIQ Score por bloques horarios.
5) App muestra score, mejor ventana, mapa y explicación de los 3–5 factores principales.
6) Asistente IA responde preguntas usando únicamente datos estructurados + base de conocimiento.
7) Después de pescar, usuario registra captura; el sistema adjunta automáticamente las condiciones del momento/lugar.
8) Datos de captura alimentan analítica; el aprendizaje estadístico avanzado se activa en fase posterior.

5. FISHIQ Score v0.1
Primera versión: motor determinístico y explicable. Cada variable se normaliza 0–100 según la especie y luego se pondera. Los pesos deben ser editables sin desplegar código.
Score = Σ (pesoᵢ × subscoreᵢ)  →  resultado 0–100

6. Arquitectura funcional sugerida
Frontend: PWA responsive (React/Next.js o equivalente), optimizada para iPhone/Android.
Backend/API: Node.js/TypeScript o Python/FastAPI; decisión del equipo, siempre con API documentada.
Base de datos: PostgreSQL + PostGIS para usuarios, spots, capturas, polígonos, especies y datos geográficos.
Cache/colas: Redis o equivalente para forecasts, jobs y control de costos.
Storage: objeto compatible S3 para fotos de capturas.
IA: endpoint server-side; nunca exponer API keys en cliente. La IA recibe JSON estructurado y base de conocimiento versionada.
Analytics: eventos de uso, consultas de score, zonas consultadas y conversión a registro de captura.
Privacidad: spots privados por defecto; coordenadas exactas no deben hacerse públicas sin consentimiento explícito.

8. Modelo de datos mínimo
Entidades: User, Species, SpeciesRuleSet, Zone, Spot, ForecastSnapshot, ScoreCalculation, Catch, Lure/Technique, AIConversation, SubscriptionPlan y ProviderLog.
Catch debe almacenar condiciones ambientales como snapshot histórico; no recalcularlas después.
ScoreCalculation debe guardar inputs, pesos, subscores, versión del algoritmo y resultado.
SpeciesRuleSet debe ser versionado para poder comparar cambios del algoritmo.
9. IA: comportamiento requerido
La IA NO inventa condiciones ni spots. Debe responder con los datos suministrados por backend.
Debe poder explicar: por qué el score sube/baja, mejor ventana, técnica sugerida y riesgos/limitaciones del dato.
Si falta un dato crítico, debe decirlo y reducir confianza; nunca completar con valores ficticios.
Respuesta en español desde el MVP; arquitectura preparada para portugués e inglés.
El sistema debe distinguir recomendación de pesca de navegación/seguridad marítima.
10. Criterios de aceptación del MVP
Un usuario puede registrarse, seleccionar zona/especie/fecha y obtener un score horario.
El score es reproducible: mismos inputs + misma versión = mismo resultado.
Cada score muestra los factores que más lo favorecen y perjudican.
Mapa carga correctamente y puede mostrar batimetría/zonas/spots privados.
Usuario puede registrar captura con foto y ubicación; se guarda snapshot ambiental.
IA puede responder usando el score y datos reales sin calcularlos por su cuenta.
Panel admin permite modificar pesos/reglas de especie sin cambiar código.
Logs permiten identificar proveedor y momento de cada dato externo.
Responsive en Safari iPhone y Chrome Android.
Privacidad: spots/capturas privadas por defecto.
